# Migrating to 0.13.0

0.13.0 adds a size check, `check-size.sh`, and a `check-size` recipe in
`release.just` that wraps it. It refuses a file over 20000 bytes, or over 10000
for a `SKILL.md`, so no file outgrows a single read. The manual chapter is
[The size check](../manual/size-check.md).

**Nothing applies with no step taken, with one exception.** `update.sh` edits
nothing outside `plugin-dev/`, and nothing in the release flow calls
`check-size`: a plugin that takes no step below is unaffected, unless its own
justfile already defines a `check-size` recipe, which step 0 repairs. The other
steps adopt the check.

## 0. Rename a recipe of your own named `check-size`

`just` refuses a recipe defined in both an import and the importer. If your
justfile already defines `check-size`, the pull has broken it: every `just`
command now fails with
``error: Recipe `check-size` first defined on line … is redefined on line …``.
Rename yours (to `size-check`, say) and update whatever calls it, then confirm
the justfile compiles. A reader who sees this note before updating can rename
first and skip the breakage.

```sh
just --list
```

## 1. Run it once, unwired

```sh
just check-size
```

A pass prints a sign-off line starting `check-size: cap 20000 bytes:`; step 5
checks for that line. Each file over a cap is one line,
`oversized-file: <path>: <n> bytes > <cap>`. Read the list before changing
anything.

## 2. Split each listed file, or exempt it

Split the file along a seam: a section that stands alone becomes a file of its
own, and a `SKILL.md` hub hands detail to nodes under `references/`. Do not
shave prose or docstrings to fit; the manual's "When it fails" says why.

For an overage you cannot split yet, create `size.exempt` at the repository
root, one entry per line, a path then ` #` and the reason:

```text
skills/review/SKILL.md # split into references/ nodes once the checklist settles
vendor/generated # regenerated by the build, not edited by hand
```

A directory entry covers every file below it, which suits a frozen or generated
tree. Every entry needs a reason that says what ends the overage. There is no
flag that seeds the file: a reason cannot be generated, and a placeholder
defeats the rule. Each entry is re-checked on every run and refused once it
stops being true; the manual's `size.exempt` section lists the refusals.

## 3. Wire it into the commit gate

Add `check-size` as a dependency of `precommit`, beside any others:

```just
precommit: check-refs check-size
```

Keep it a dependency, not a line inside a cached gate body: it reads every file
git does not ignore, which a gate's pathspecs rarely cover, so a cached pass
could commit a file it never read.

## 4. Retire a checker it replaces

If the plugin already enforces a line cap of its own, the old 400-line or
200-line rule, as a test, a script or a gate step that reports something like
`oversized-file: <n> lines`, remove it in the same commit. The two measures
disagree, and a file can pass one and fail the other. Remove whatever called it
too: helpers, fixtures and doc mentions.

## 5. Prove it, and commit

```sh
just check-size
just precommit
```

The first prints the `check-size: cap 20000 bytes:` sign-off line and the second
passes. Commit the splits, `size.exempt`, the justfile change and any retired
checker as their own commit, separate from the subtree-pull merge.
