# Migrating to 0.12.0

0.12.0 adds a reference check, `check-refs.sh`, and a `check-refs` recipe in
`release.just` that wraps it. It refuses a Markdown link, image or reference
definition whose relative target does not exist, and, in a plugin with a
`dist.include`, a link from a shipped file to a file the list leaves out. The
manual section is [Reference check](../README.md#reference-check).

**One part applies with no step taken.** For a plugin with a `dist.include`,
the release now runs the shipped half of the check on the tree it builds, and
refuses before any commit or tag when a shipped Markdown file links to a path
the tree does not hold. A README that links into an unlisted `docs/`, or a
shipped changelog record that links into `plans/`, refuses the next
`just release`. A plugin without a `dist.include` sees no change at release.

## 1. Run it once

```sh
bash plugin-dev/check-refs.sh
```

Each broken reference is one line, `docs/a.md:12: target — reason`. A pass
prints the counts. For each line, one of:

- **does not exist**: fix the target, or drop the link. A frozen record under
  `docs/changelog/` or `plans/` is exempt already; see step 3 for others.
- **is not shipped**: list the target in `dist.include`, or drop the link from
  the shipped file. A README link into design material under `docs/` is
  dropped, not fixed by listing `docs`; see the convention under "The manual
  directory". Exemptions do not apply here: a shipped file's dead link ships.

A backticked path is never checked; only real links are. A target must be a
file git lists, tracked or untracked, so a link to a gitignored file is refused
("is ignored by git"), and so is one with the wrong case on a case-insensitive
disk. A link to an untracked file passes here, but a release refuses it until
the file is committed.

## 2. Wire it into the commit gate

Add `check-refs` as a dependency of `precommit`, beside any others:

```just
precommit: check-refs
```

A dependency runs on every call, ahead of the recipe body. In a gate that opens
with `plugin_dev_gate_prolog`, that keeps it out of the cache: it reads every
Markdown file on disk that git does not ignore, which a gate's pathspecs rarely
cover. Run `just --list` to confirm the justfile still compiles; a recipe of
your own named `check-refs` is the only conflict.

## 3. Exempt other frozen records, if you keep any

Files under `docs/changelog/` and `plans/` are skipped by the resolve check,
since a dated record's link to a file deleted later is still true. To exempt
other paths, create `refs.exempt` at the root, one path per line with `#`
comments. It replaces the defaults, so list them again if you keep them:

```text
# dated records and plans
docs/changelog
plans
reports
```

## 4. The manual directory

The toolkit's manual chapters moved from `plugin-dev/docs/` to
`plugin-dev/manual/`: `dist-branch.md`, `dogfood.md` and `gates.md`. Search your
README, justfile comments and notes for `plugin-dev/docs/` and change each to
`plugin-dev/manual/`. The `install.sh` hint and the `gates.just` comment already
say the new path.

Recommended, for a plugin with a `dist.include`: keep what a user reads in a
`manual/` directory and list `manual`; never list `docs`, where design material
belongs and which would ship it. The README links into `manual/` relatively, and
reaches design by at most one absolute URL, in a Development line. Nothing
enforces this; `check-refs` only refuses the links that dangle.

Commit the fixes and the justfile change as their own commit, separate from the
subtree-pull merge.
