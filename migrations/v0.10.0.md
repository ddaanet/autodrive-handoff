# Migrating to 0.10.0

Nothing changes for a plugin without a `dist.include`: the release, the
dogfood sync and the marketplace entry it already has behave as before. Two
things differ for every plugin. A marketplace entry the release creates now
carries an https `url` source in place of a `github` one, which cloned over SSH.
An existing entry's `source` is never rewritten. And `dist.sh` is a new file in
`plugin-dev/`, which `update-plugin-dev` brings in.

The steps below are for a plugin that wants a `dist` branch, because its plugin
folder is its repo root and holds a gitlink the plugin directory refuses.

1. Create `dist.include` at the repo root, one shipped path per line, relative
   to the root, and commit it:

   ```sh
   printf '%s\n' .claude-plugin skills hooks scripts README.md LICENSE > dist.include
   git add dist.include
   git commit -m "add the dist allowlist"
   ```

   List only paths that exist; a listed path matching nothing is refused. Drop
   `LICENSE` if the plugin has none and sets `license` in `plugin.json`.

2. Check that `claude` is on PATH, since the release validates the tree with
   `claude plugin validate --strict` before it commits or tags.

3. Run `just dogfood` and look in `dist/plugin/`. It now holds only the listed
   paths. A refusal names the line or the path.

4. Run `just release`. The first release creates the `dist` branch and a
   `dist-vX.Y.Z` tag, and sets `ref: dist` on the marketplace entry. Check the
   branch:

   ```sh
   git ls-remote origin refs/heads/dist
   ```

   One line, the sha of the commit titled `dist vX.Y.Z from <sha>`. No line
   means the release did not reach the dist step; run `just resume-release`.

5. Point the plugin directory submission at the `dist` branch.
