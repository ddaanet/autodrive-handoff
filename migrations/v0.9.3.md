# Migrating to 0.9.3

The version-guard hook command now double-quotes `${CLAUDE_PROJECT_DIR}`. The
command earlier releases wrote into `.claude/settings.json` was unquoted, so a
plugin checked out under a path with a space ran `bash` on the part of the path
before the blank, got exit 127, and the guard failed open: Claude Code treats
that exit as a non-blocking hook error and nothing says so. `update-plugin-dev`
does not rewire `settings.json`, so the existing entry keeps its old spelling
until the installer runs again.

1. Re-run the installer from the plugin's root, in your own shell rather than an
   agent's sandboxed Bash, which refuses writes to `.claude/settings.json`:

   ```sh
   bash plugin-dev/install.sh
   ```

   It rewrites the unquoted version-guard entry in place, under whatever matcher
   you gave it, and prints `settings.json (version-guard hook requoted)`. If the
   quoted entry was already there beside the old one, it removes the old one.
   Run on a plugin that has nothing to migrate, it says so and changes nothing.

2. Check that one quoted entry remains:

   ```sh
   grep version-guard .claude/settings.json
   ```

   One line, with the variable inside escaped double quotes, JSON's spelling of
   the quoted command:
   `"command": "bash \"${CLAUDE_PROJECT_DIR}/plugin-dev/version-guard.sh\""`.
   Two lines, or one without the backslashes, means the installer did not run to
   the end; re-run it.

3. Commit `.claude/settings.json`.
