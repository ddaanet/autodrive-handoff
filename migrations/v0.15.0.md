# Migrating to 0.15.0 (breaking)

0.15.0 adds a frontmatter check, `check-frontmatter.sh`, and a
`check-frontmatter` recipe in `release.just` that wraps it. It refuses a skill,
agent or command whose frontmatter is missing, not YAML, or breaks the toolkit's
field rules. The manual chapter is
[The frontmatter check](../manual/frontmatter-check.md).

**Nothing applies with no step taken.** `update.sh` edits nothing outside
`plugin-dev/`, and nothing in the release flow calls `check-frontmatter`: a
plugin that takes no step below is unaffected, unless its own justfile already
defines a `check-frontmatter` recipe, which step 0 repairs. The other steps
adopt the check.

## 0. Rename a recipe of your own named `check-frontmatter`

`just` refuses a recipe defined in both an import and the importer. If your
justfile already defines `check-frontmatter`, the pull has broken it: every
`just` command now fails with
``error: Recipe `check-frontmatter` first defined on line …``. Rename yours (to
`frontmatter-check`, say) and update whatever calls it, then confirm the
justfile compiles.

```sh
just --list
```

## 1. Add the venv if the plugin has none

The check parses YAML with PyYAML, found through `python3` on PATH. Add `pyyaml`
to the dev group of `pyproject.toml`, run `uv sync`, and put `.venv/bin` on PATH
from `.envrc` with `PATH_add .venv/bin`. The chapter's Setup section has the
lines.

## 2. Run it once

```sh
just check-frontmatter
```

Each problem is one line, `check-frontmatter: <path>: <reason>`; a pass prints
`check-frontmatter ok (<n> skills, <n> agents, <n> commands)`. Fix each file.
The check stops at the first kind of problem in a file, so a block refusal hides
`name` ones: re-run until it passes.

## 3. Give each skill and agent a `name`

The check requires a `name` in a skill and an agent, and a skill's must equal
the directory holding its `SKILL.md`; an agent's need not match its file name.
Claude Code defaults a skill's `name` to its directory, so a file you wrote
without one may need it added before wiring the check. A skill whose `name`
differs from its directory has two fixes. In a plugin, a skill's `name` is the
last segment of its command, so changing `name` to the directory renames the
command and breaks references to the old one; renaming the directory to the
`name` passes the check and keeps the command. The reasons appear as
`name is missing` or `name ... differs from its directory ...`. A command's
`name` stays optional.

## 4. Wire it into `precommit`

Nothing wires it for you. Add it by hand beside the other checks:

```just
precommit: check-refs check-size check-frontmatter
```

Confirm with `just --dry-run precommit` that the dependency is listed.
