# Migrating to 0.9.1

The `claude` shim no longer syncs. A launch, a `claude -c` relaunch, or any
other `claude` you run in the repo loads `dist/plugin/` as it stands, and
`just dogfood` is the only step that promotes the working tree into it.

1. From the plugin's root, in your own shell rather than an agent's sandboxed
   Bash, create or refresh the copy before your next launch:

   ```sh
   just dogfood
   ```

   Without a copy the shim prints
   `dogfood: no copy at <root>/dist/plugin, so claude starts without it; run just dogfood to create it`
   and launches a session that does not load the plugin.

2. From now on, run `just dogfood` whenever a change should go live. An agent
   definition or hook event then needs a relaunch as well: a relaunch alone
   loads the copy last promoted. The same holds for a script that runs
   `claude -p` against the plugin, such as an eval under `just prerelease`: it
   loads the copy last promoted, so run `just dogfood` first when the run should
   see the working tree.
