# Proposal: port the handoff plugin to Vibe

2026-11-23. Status: approved and executed the same day, with the default on
each open question (native Vibe plugin; the consumer loader line reads
`TASK.md` and `TODO.md`; the gitlore seam kept and the hold instruction
dropped; skill bodies ported side by side). Sources: the handoff frame
(`TASK.md`/`TODO.md` it continues), the memory entry
`vibe-plugin-portability` (verified 2026-11-22 against mistral-vibe 3.0.1),
and `docs/design.md` for the plugin being ported. The landed shape is
`docs/design/vibe-port.md`.

## What Vibe takes away

From `memory/vibe-plugin-portability.md`, the constraints any port lives with:

- **Hook surface is `post_agent`/`pre_tool`/`post_tool` only.** No
  SessionStart, no UserPromptSubmit, no PreCompact. The Claude adapter maps
  just those three and refuses executable `.js`/`.ts`, so the mod cannot run
  in any form. `/compact` keeps the session id; `/clear` starts a new one.
- **Skill tool prints its base directory**, so scripts shipped inside a skill
  directory are callable by absolute path. `PLUGIN_ROOT` reaches MCP servers
  only.
- **AGENTS.md is spliced verbatim** — no `@` import, so file content crosses
  only by instructing the agent to read. **CLAUDE.md is never read.**
- **No native memory**; gitlore is the only durable carrier.
- `post_tool` `additional_context` works and the stdin payload carries
  `session_id` — the one mechanical injection, unused by the decided shape
  but kept on the map.

## The decided shape

The port is not a translation of the transition machinery. It is the content
and the write path, with the driving dropped:

- **The four skills port**: `handoff`, `precompact`, `autoname`, `pending`.
  Each carries `scripts/checkpoint.py` — and its module siblings
  `_checkpoint_payload.py`, `_checkpoint_plan.py`, `_checkpoint_lib.py`, which
  `checkpoint.py` imports — inside the skill directory. The skill body names
  the invocation through the base directory the skill tool prints; the
  payload stays the schema-validated JSON object on stdin.
- **One AGENTS.md line** in the consuming repo reads `TASK.md` and `TODO.md`
  before the first reply. That is the frame injection; there is no loader
  script because there is no SessionStart.
- **The compact seam is a custom compaction prompt** (`compaction_prompt_id`)
  instead of the `SessionStart(compact)` loader; the `precompact` skill
  composes it.
- **Memory rides gitlore alone.** The checkpoint directive keeps the
  `gitlore:commit` act when the memory store is dirty (default, in question
  below).
- **Dropped, not ported**: the mod (`hooks/handoff.ts`), `write-guard.sh`,
  the sentinel (`.claude/autodrive`) with its grammar and lock, the hold
  predicate (`handoff-approved`/`held`, `driven`, `with-commit` gating). No
  driven continuation exists: the turn ends and the next session starts from
  the frame the AGENTS.md line reads.

## Open questions

1. **Where the Vibe variant lives** (`TODO.md` open decision). A native Vibe
   plugin next to the Claude manifest versus relying on Vibe's Claude-format
   adapter to import the existing tree. The adapter import needs no copied
   files but drags the whole `hooks.json` along: the SessionStart loaders are
   reported unsupported, and `pre_tool`/`post_tool` entries compile with
   unrenamed matchers — `Write`/`Edit`/`Bash` matchers never fire under Vibe's
   tool names, so `inject-checkpoint-root.sh` would silently stop exporting
   `HANDOFF_ROOT`. Silent no-ops from a foreign file are the failure mode a
   native variant avoids by shipping only what ports. Default: native Vibe
   plugin, skills carrying their own scripts.
2. **The consumer loader line's scope** (`TODO.md` open decision). `TASK.md`
   and `TODO.md` only, or also the repo's memory entry-point. Non-ported
   repos have no `memory/` directory, and the plugin line cannot assume the
   ddaanet layout; a line that names an absent file costs a failed read on
   every session start in every consumer. Default: the plugin line reads
   `TASK.md` and `TODO.md` only; repos that want memory in the first read
   extend the line in their own AGENTS.md, as this repo's now does.
3. **How much of the checkpoint directive survives.** The directive parts
   (`docs/design/the-checkpoint-directive.md`) assume the sentinel: the
   `handoff-approved` closing instruction and the `with-commit` gating have
   no counterpart. Default: the gitlore seam (dirty store → invoke
   `gitlore:commit`) stays, the hold instruction goes, and the directive's
   Vibe text is rewritten in the port rather than conditioned at runtime.
4. **Whether the skills' SKILL.md bodies fork.** The Claude skills reference
   `${CLAUDE_PLUGIN_ROOT}`-removed paths and the checkpoint stdout's cell
   format. Default: the Vibe skill bodies are ports of the same text,
   diverging only where the Vibe mechanism differs (base-directory path, no
   approved instruction), reviewed side by side rather than generated from
   one source; when the port is small the fork is cheaper than a template.
