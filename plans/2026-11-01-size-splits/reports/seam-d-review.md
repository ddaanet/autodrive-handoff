## Findings

### 1. `skills/handoff/SKILL.md:28`: medium. `handoff` times the Read "before drafting", and every other statement says "before deciding"

What is wrong: `handoff` Step 2 says "Read `references/files.md` … before drafting". In that step, drafting is the last part of deciding. The clear, continue and commit answers come first (37-60), and then "decide the content: … draft the content using the task template" (62-71). The rule is "no tool call between deciding and `handoff-checkpoint`" (32). `precompact:27`, `.claude/rules/skills.md:25` and `decisions.md:272-273` all put the Read "before deciding". Two other places carry the drafting wording: `the-skills.md:19` ("which both skills read before they draft") and `decisions.md:268` ("read as part of drafting"). The last of these contradicts its own entry four lines later.

Reading that goes wrong: an agent works through Step 2, settles `clear`, `continue`, `commit` and the title, and reaches the task snapshot. The text tells it to Read `files.md` before drafting, so it Reads there. That Read lands between deciding and the checkpoint, which the bold line forbids. The live run read first because the paragraph sits first. The wording still licenses the later Read.

Fix direction: change "before drafting" to "before deciding" in `handoff/SKILL.md:28`. Change `the-skills.md:19` to "before they decide", and `decisions.md:268` to "read before deciding". `skills/handoff/references/files.md:1` also carries the wording ("read by … before they draft"). It is descriptive, since its reader has already done the Read, but it is the same phrase and goes in the same edit. The `handoff` Step 3 pointer (110-111) is a fourth mention, left where the moved sections sat and now inside Step 3, after the call. It can go in the same edit, since Step 2 and `## Additional resources` both carry the pointer (see declined item 4).

### 2. `.claude/rules/skills.md:15`: medium. "neither `SKILL.md` … restates them" is contradicted by both skills

What is wrong: the rewritten bullet now claims that no `SKILL.md` restates the templates. `precompact/SKILL.md:60-62` restates the todo template's shape: "`## Open decisions`, when any remain, plus `## Remaining`, open items only". `handoff/SKILL.md:122-129` names `## Current task` and `## Open decisions` in its anti-patterns. The old bullet claimed only that the loaders did not restate the templates.

Reading that goes wrong: whether naming a heading counts as "restating" does not matter here. A maintainer who changes a todo heading in `files.md` trusts the rule, searches only `files.md`, and leaves `precompact`'s copy alone. `precompact` then prescribes sections the template no longer has.

Fix direction: drop "neither `SKILL.md` nor" and keep "neither loader restates them", which is true and was the old claim. Do not edit the skills to match the stronger claim.
